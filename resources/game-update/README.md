# 游戏资源更新

2026-09-17 从 MuMu 2560×1440 游戏画面提取的无损模板：

- `message.png`：固定文案“当前游戏版本需要更新，本次更新文件大小约为”，不包含下载大小。
- `confirm.png`：该弹窗的蓝色“确定”按钮。
- `downloading.png`、`checking.png`：下载和校验阶段的固定文案，不包含进度数字；下载期间优先本地等待，暂停后再次采样可接续等待。

只有两个模板同时命中、相对位置一致、前台包名正确，才确认资源下载。下载大小变化不影响匹配；普通确定按钮、退出确认、购买弹窗不会仅凭按钮命中而执行。完整截图保存在本地 `.wl-data/diagnostics/`，不提交公开仓库。

处理器为 `src/main/game/update.ts`，自动采集和队列采样共用。点击前重截一帧验证；只点一次；最长等待 15 分钟；每 3 秒本地检查主界面，每 30 秒最多尝试一次原有 AI 关闭公告流程。等待不消耗队列采样的普通超时预算，停止操作可打断等待。

更新超时、确认未生效或前台改变时，明确提示更新待处理并暂停自动调度，不计入设备掉线次数。处理后在面板点击恢复。其它布局的更新提示可通过 [AI 风险评估](../../docs/ai-risk-control.md) 和点击前复核确认，无需先制作模板；风险不明时暂停。

离线回归：`npm run check:runtime`；覆盖实际模板、多分辨率、普通确认框拒绝、点击前画面变化、单次确认、取消、等待超时、慢下载及采样时限。

实机验证：2026-09-17，实例 #0 的 176.62 MB 更新已由程序自动确认并完成；随后进入城内、切到世界地图、成功读取 5/5 部队队列，恢复自动调度。
