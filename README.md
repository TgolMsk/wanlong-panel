# 万龙控制面板

MuMu 模拟器多实例控制面板 —— **截图 + 模板匹配**的多账号自动化地基。

一个 Electron 桌面面板：管实例、连 adb、抓帧、匹配模板、跑脚本、多实例并发、看实时日志与预览。
地基部分**不含任何具体游戏的逻辑** —— 通用游戏逻辑靠往「模板集 + 脚本 JSON」里填内容实现，不用改代码。
在此之上另有一个内置的完整功能块：**《万龙觉醒》自动采集资源**（见第 6 节），
它需要读数字、算等级、排 ETA，脚本 DSL 表达不了，所以做成了原生流程。

## 1. 安装

支持三套环境，按平台自动选默认驱动（设置页可改）：

| 平台 | 模拟器 | 管理 CLI | 状态 |
|---|---|---|---|
| **Windows 10/11** | **MuMu 模拟器 6.x**（新一代「MuMu模拟器」，MuMu 12 应该也行，未测） | `<MuMu 目录>\nx_main\MuMuManager.exe` | 2026-09-14 真机验证（6.6.4.0，Android 15） |
| **Windows 10/11** | **雷电模拟器 14**（9 应该也行，未测） | `<雷电目录>\ldconsole.exe` | 2026-09-14 真机验证：`live:probe` 7/7、`live:panel` 读数全部正确 |
| macOS（Apple Silicon） | MuMu Pro | `mumutool` | 工程最初的环境 |

### 1.1 Windows + MuMu 模拟器（默认）

前置条件：Node 22+、已安装 MuMu 模拟器并在多开器里建好实例。**实例分辨率必须是 2560×1440、DPI 360**
（模板库全部截自这个尺寸；MuMu 里选「平板 2560×1440」或自定义都行，面板的实例列表与环境自检会把不一致的实例标出来）。

```powershell
npm ci               # npm 10 直接可用；npm 11 再执行 npm run approve
npm run dev          # 起面板
```

面板启动时自动探测 MuMu 安装目录（卸载注册表 `HKLM\...\Uninstall\MuMuPlayer\InstallLocation`
→ 常见目录 → 正在运行的 MuMu 进程），把 `MuMuManager.exe` 与 `adb.exe` 的路径写进 `settings.json`
（都在 `<MuMu 目录>\nx_main\`，MuMu 12 是 `\shell\`）；探不到就到「设置」页手动选择，环境自检会告诉你缺什么。

adb 端口不是公式，由 `MuMuManager info` 动态给出（实例 0 实测 16384，只在实例启动后才有），面板每次现读。
实例配置**能读能写**：实例页「写入配置」支持 `resolution` / `cpu` / `memory` / `root` 等友好键，
也可以直接写 MuMuManager 的原始键（如 `"performance_mode": "high"`）；写入后要重启实例才生效。
空白新建默认填 `{"resolution": "2560,1440,360"}`；克隆出来的实例名是「<原名>-<序号>」。
实例行「更多 → 设为基础实例」可指定后续新建的默认来源；设好后新建默认从它克隆，也可临时选择空白新建。
克隆前先关闭基础实例，支持一次创建 1–8 份，详情见 [基础实例说明](docs/base-instance.md)。
创建后默认进入手机号验证码[账号登录向导](docs/account-login.md)，完成进入游戏的检查后再启用账号。登录流程素材、控件记录和未来 API 服务接口一并保留。

命令行验证：

```powershell
D:\tool\MuMuPlayer\nx_main\MuMuManager.exe info -v all          # JSON，按实例序号为键
D:\tool\MuMuPlayer\nx_main\MuMuManager.exe control -v 0 launch  # 1.8 秒返回，约 8 秒后 is_android_started 变 true
D:\tool\MuMuPlayer\nx_main\adb.exe connect 127.0.0.1:16384
```

### 1.2 Windows + 雷电模拟器

雷电驱动完整保留，到「设置」页把模拟器改成「雷电模拟器」、把两个路径**清空后保存**即可
（面板会按注册表 `HKCU\SOFTWARE\leidian\LDPlayer*` → 常见目录重新探测，自动换成 `ldconsole.exe` 与雷电自带的 `adb.exe`）。
同样要求实例分辨率是自定义 2560×1440、DPI 360。

雷电的 adb 端口是固定公式 **5555 + 2×实例序号**（序号 1 = `127.0.0.1:5557`），面板自动算，不用填。
Hyper-V / 内核隔离开着也能跑（雷电 14 从 2026-03 起兼容）。

★ **两家换来换去时注意两件事**：

1. **保存后重启面板生效**。账号、调度、告警和采集状态按模拟器种类与安装路径隔离，
   切回原来的模拟器会恢复原数据。首次升级沿用当前数据，另一套模拟器从独立目录开始；模板与脚本在同一数据根目录内共享。
2. **两家的 adb 版本不同**，共用 5037 端口时可能冲突。重启后使用所选模拟器自带的 adb，
   若自检提示冲突，再关闭另一家的 adb 客户端并重试连接。

详见 [运行可靠性与数据切换](docs/runtime-improvements.md)。

游戏启动遇到已校准的资源更新弹窗时，会自动确认下载并等待加载完成，再继续采样或采集。下载期间可停止；更新超时会单独提示处理。详见 [游戏更新处理及素材](resources/game-update/README.md)。

AI 接管按按钮的实际后果评估风险，低风险的确认、继续和重试可在新截图复核后执行，风险较高或不明时暂停并说明原因。详见 [AI 风险判断与确认流程](docs/ai-risk-control.md)。

### 1.3 macOS + MuMu Pro

前置条件：macOS（Apple Silicon 已实测）、Node 22+、已安装并**至少启动过一次** MuMu Player。

```bash
npm install
npm run approve      # npm 11 的 install-scripts 白名单，首次必须批准（esbuild / sharp）；npm 10 会自动跳过
```

`npm run approve` 在 npm 11 下是必须的：它默认不跑依赖的 postinstall，跳过它 esbuild 会缺二进制。

Electron 的二进制**不是**靠 postinstall 下载的（electron@44 改成了首次 `require('electron')` 时懒下载）。
如果起面板时报 `Electron failed to install correctly`，手动补一次：

```bash
node node_modules/electron/install.js
```

下载慢的话，把 `.npmrc` 里那行 `ELECTRON_MIRROR=...` 的注释去掉再重试。

面板会自动找这两个可执行文件（都在 MuMu 安装包里，系统 PATH 里没有）：

```
adb      /Applications/MuMuPlayer.app/Contents/MacOS/MuMuEmulator.app/Contents/MacOS/tools/adb
mumutool /Applications/MuMuPlayer.app/Contents/MacOS/mumutool
```

路径不对可以在面板的「设置」页改，或改 `src/shared/constants.ts` 里的默认值。

### 1.4 命令行脚本怎么找模拟器

`smoke` / `live:*` / `tplkit` 这些脚本不读面板的设置文件，按环境变量自己解析：
`WL_EMULATOR=ldplayer|mumu`（**默认 mumu**，用雷电要显式设 `WL_EMULATOR=ldplayer`）、
`WL_MUMU_DIR=<MuMu 目录>`、`WL_LDPLAYER_DIR=<雷电目录>`、`WL_EMULATOR_CLI`、`WL_ADB`、`WL_INSTANCE=<实例序号>`
（多个实例在跑时指定用哪个，不指定取第一个运行中的）。PowerShell 里这样写：

```powershell
$env:WL_INSTANCE = '0'; npm run live:probe
```

## 2. 起面板

```bash
npm run dev
```

左侧导航集中为五个入口，相关页面在内容区顶部切换：

| 主入口 | 包含页面 |
|---|---|
| **设备与账号** | 模拟器实例、账号管理 |
| **自动采集** | 采集总览、采集配置 |
| **运行记录** | 执行监控、数据统计 |
| **高级工具** | 脚本、模板库、AI 处理 |
| **设置** | 面板配置、环境自检、通知与设备工具 |

左下角可收起导航，为表格和画面腾出空间。实例列表支持按名称、序号或账号搜索和按开机状态筛选，默认按实例序号排列；展开行可查看连接地址、端口和分辨率。「重启」「断开连接」「克隆」「写入配置」「删除」集中在「更多」菜单中。

实例列表的「自动采集」列可以直接给某个实例开 / 关自动调度、点「采样」立刻读一次「部队管理」面板（与「采集总览」页的开关、按钮是同一套通道）；被异常暂停的实例会在这里标出并给「恢复」按钮，采集配置总开关没开或没绑账号也会标黄提醒。右上角「批量采集」菜单对当前筛选出的实例一键全部开启 / 关闭 / 采样（未开机、已暂停、基础实例自动跳过，结果里会说明；全部开启前会弹确认）。「更多」菜单里还有「采集配置」直达。

程序 Logo 用于侧栏、窗口图标和安装包。源图及 PNG / ICO / ICNS 文件在 `resources/brand/`；执行 `npm run icons:app` 可重新生成各尺寸，设计提示词与路径见 [品牌资源说明](docs/brand.md)。

面板默认是**暗色主题**（靛蓝 + 薄荷绿），右上角的小太阳可以切亮色，选择记在本机。
面板还会记住你上次停留在哪一页。

**实例列表里的「adb 链路」默认是「未连接」，这是设计如此**：面板不自动连接，
点这一行的「连接」按钮才会 `adb connect` 并采集设备信息。截图/脚本都要求先连上。

其它命令：

```bash
npm run typecheck    # tsc --noEmit（node + web 两套工程都查，含 scripts/）
npm run build        # typecheck + electron-vite build
npm run dist:win     # 打 Windows 安装包 + 免安装版（electron-builder --win --x64，未签名，SmartScreen 会提示一次）
npm run dist:mac     # 打 dmg（electron-builder --mac --arm64）
npm run format       # prettier
```

### 发布安装包（GitHub Actions）

仓库带了一条工作流 `.github/workflows/release.yml`，在 GitHub 的 Windows 机器上跑 `npm ci → npm run build → electron-builder --win --x64`，
本地不用装任何东西：

| 触发 | 结果 |
|---|---|
| 推到 `main` | 只构建；安装包挂在这次运行的 **Artifacts** 里（登录后可下，默认保留 90 天） |
| 推 `v*` 标签 | 构建 + 自动创建同名 **Release**，`wanlong-panel-<版本>-win-x64.exe`（安装版）与 `wanlong-panel-<版本>-portable-x64.exe`（免安装）作为附件公开下载 |
| Actions 页手动触发 | 只构建、只传 Artifacts |

发一个版本：

```bash
npm version 0.3.0 --no-git-tag-version   # 改 package.json / package-lock.json 的 version
git commit -am "release: v0.3.0"
git tag v0.3.0
git push origin main v0.3.0                # 标签一到 GitHub 就开始构建，约 6~10 分钟后 Release 页面出现安装包
```

附件文件名用的是 package.json 的 `name`（ASCII）而不是「万龙面板」：GitHub 会把附件名里的中文规范化成一串点。
安装后的程序名、快捷方式仍然是「万龙面板」。没做代码签名，首次运行 SmartScreen 会提示「未知发布者」，点「仍要运行」即可。
只想在打标签时才构建的话，把工作流里 `on.push.branches` 那两行删掉。

## 3. 跑冒烟自检

**这是验证「环境 + 代码」是否真的通了的唯一权威手段。** 每次改了 adb / 视觉 / 脚本引擎都该跑一遍。

```bash
npm run smoke
```

前置：MuMu 里**至少有一个实例正在运行且画面已出来**。其余不需要准备，模板是它自己从真帧里裁的。

它按顺序验证五件事，全部打真实耗时，最后给一张 ✅/❌ 汇总表：

| # | 验证什么 | 用到的封装 |
|---|---|---|
| 1 | 列出实例：index / 名称 / state / adb_port / serial | `listInstances()` |
| 2 | 连接并抓一张真实截图，落到留痕目录 | `attach()` / `captureRaw()` / `saveShot()` |
| 3 | 从真帧里自动挑一块高方差区域存成模板，再匹配回去；**外加一个负样本对照** | `saveTemplate()` / `loadPrepared()` / `matchIn()` |
| 4 | 输入注入：`APP_SWITCH` 让画面变、`HOME` 让画面复原 | `key()` |
| 5 | 脚本引擎最小任务六步：log → waitFor → tapTemplate → 截图留痕 → key → log | `Engine` / `RunContext` |

本机实测输出（MuMu 实例 0，2560x1440）：

```
✅ [1] 实例列举：1 个实例，1 个 running；index=0「我的安卓」adb_port=16384；耗时 56ms
✅ [2] 真实截图：2560x1440，14.06MB，captureRaw 中位 701ms（去节流 280ms）
✅ [3] 模板匹配：正样本 score=0.999 偏差 (0,0)px 耗时 7ms；负样本 found=false score=-0.4802
✅ [4] 输入注入：APP_SWITCH 后画面平均绝对差 124.02；HOME 后降回 0.00，模板重新命中
✅ [5] 脚本引擎：status=succeeded，6 步，1196ms，匹配命中 2/2，点击 1 次，日志 8 条，留痕 1 张
```

**负样本那一列是重点**：正样本 0.999、负样本 −0.48，说明匹配是真有判别力的，
而不是「不管看到什么都说命中」。只看正样本的自检等于没做。

产物：

```
docs/smoke-capture.jpg     人眼可看的当时画面
docs/smoke-report.json     机器可读的完整报告（设备信息 / 模板定义 / 匹配结果 / 执行快照）
docs/panel.png             面板窗口截图（手动截的，不是 smoke 生成的）
.wl-data/…                 留痕截图、ndjson 日志、冒烟模板集（见第 7 节）
```

冒烟脚本本体在 `scripts/smoke.ts`。它被 esbuild 打包成 `out/smoke/smoke.mjs` 再用 node 跑
（`npm run smoke` 已经把两步串好了），这样才能解析工程里的 `@shared` / `@main` / `@vision` / `@worker` 别名。

**它做了什么、没做什么**（安全边界写死在代码里）：

- 只**读**实例列表，绝不 create / clone / delete / open / close / restart。
- 绝不安装或卸载任何应用，绝不改设备设置。
- 输入只用 `HOME` / `APP_SWITCH` 两个按键，外加一次落在**画面空白处**的点击 ——
  空白点是「全屏方差最低的区块中心」算出来的，不是猜的坐标，保证点不到任何图标。
- 结束时**不** `adb disconnect`，保持你进入时的连接状态。
- 会按一次 `HOME` 把前台应用切到后台（不是关闭），因为桌面是静止画面，
  拿动来动去的游戏画面当模板等于给自检自己造不确定性。

## 4. 怎么加模板

模板 = 从游戏画面里裁下来的一小块图，脚本靠「这块图出现在哪」来判断当前是什么界面、该点哪。

### 在面板里加（推荐）

1. 「实例管理」里把目标实例**连接**上。
2. 去「模板库」→ 新建模板集（一个游戏一个集合就够）。
3. 选实例 → 点「抓一帧」→ 在画布上**拉框**框住目标 → 填中文名 → 保存。

### 三条会让你少走弯路的规矩

1. **别框纯色块或渐变背景。** 低方差模板会让 `TM_CCOEFF_NORMED` 彻底退化 ——
   实测两个纯白模板对**任意**画面都恒定返回 1.0000 @ (0,0)，脚本会在完全错误的位置疯狂点击。
   面板会在标准差 < 12 时**拒绝保存**并给中文提示，这不是找茬，是救命。
   框有图标、有文字、有明确边缘的区域，标准差通常在 50 以上。
2. **尽量给 ROI（搜索区）。** 不填的话保存时会按模板位置自动外扩一个，一般够用；
   但手动收窄收益很大：实测全屏匹配 18ms、导航条区域 2ms、单个按钮区域 1ms，最多能差 43 倍。
3. **别框会动的东西。** 数字倒计时、跑马灯、粒子特效、头像框呼吸光效都不行。
   框旁边那个不动的图标或文案。

### 模板存在哪

```
.wl-data/templates/<模板集id>/manifest.json    模板集清单（唯一真相，可以手改）
.wl-data/templates/<模板集id>/<模板id>.png     模板图片（PNG 无损，不要换成 JPEG）
```

`manifest.json` 是纯 JSON，可以直接编辑（改 `threshold`、改 `defaultRoi`、改名字），
改完面板刷新一下就生效。手改后如果模板方差不达标，加载时会**跳过它并在 stderr 给中文原因**，
脚本用到时报「模板不在已加载的模板集里」。

## 5. 游戏装好后，从哪里开始写脚本

完整版见 `ARCHITECTURE.md` 第 7 节。这里是最短路径：

**第 1 步 · 统一分辨率。** 所有实例设成同一个分辨率（默认参考系是 2560x1440 横屏）。
不统一的话模板会跨实例失配 —— 引擎会用 sharp 缩放兜底，但那条路每帧多花 60ms。

**第 2 步 · 建模板集，把关键界面的锚点都截出来。** 一般 10~20 张就够跑通一条主线：
主界面的标志性图标、每个弹窗的标题、每个「确定 / 取消 / 关闭」按钮、加载中的转圈。

**第 3 步 · 从内置示例脚本改起。** 「脚本」页里有两个内置示例（`src/scripts/builtin.ts`）：

- **示例·等模板出现后点击** —— `waitFor` → `tapTemplate` → 截图。90% 的自动化步骤都是这个骨架。
- **示例·应用保活巡检** —— `loop` + `if` + `onFail: restartApp` 的写法参考。

在面板里「另存为」成你自己的脚本，把里面的占位模板 id（`demo_target`）和占位包名
（`com.example.app`）换成真的，就能跑。用户脚本落在 `.wl-data/scripts/<id>.json`，也可以直接手写 JSON。

**脚本 DSL 是纯数据**，全部步骤类型定义在 `src/shared/script.ts`：

```
tap  tapTemplate  waitFor  swipe  longPress  text  key  sleep
launchApp  stopApp  screenshot  log  label  goto  if  loop
```

每一步都支持 `when`（条件才执行）、`retry` / `retryDelayMs`、
`onFail`（`abort` / `continue` / `goto` / `restartApp`）、`afterDelayMs`、`capture`。

**第 4 步 · 单实例试跑，盯着「执行监控」调。**
开预览 + 开「显示匹配框」，看模板是不是真的框中了目标；没命中就调 ROI 或降阈值（默认 0.85）。

**第 5 步 · 绑账号 → 多实例并发。**
「账号」页建账号 → 绑到实例 → 每个实例跑一份同样的脚本。
并发上限建议 **3~4**（实测单实例跑 Unity 游戏 45.7% CPU + 1.2GB 内存），设置页可调。

**什么时候才该改代码**：需要一种新的**动作类型**（比如多指手势、OCR 读数字）时才动 `src/`。
「多点一个按钮」「多判一个弹窗」永远只该加模板和步骤，不该改代码。

## 6. 自动采集资源（《万龙觉醒》）

这是目前唯一一个**内置的完整游戏功能块**：自动搜资源点、派采集队、按 ETA 排下一次唤醒。
它**不走脚本 DSL**（DSL 表达不了「读数字 → 算等级 → 决定派谁」这类逻辑），
而是一条原生流程，代码在 `src/main/game/gather/`。

### 6.1 它到底做什么

一轮（cycle）从「确认在世界地图」开始，到「派完能派的队并算出下次唤醒时刻」为止：

```
G0 回世界地图 → G1 读部队管理面板（队列 N/M、各队倒计时/坐标/资源）→ G2 判定能不能派
G3 开搜索面板 → G4 选资源分类 → G5 探测等级上限 → G6 设搜索下限 → G7 搜索
G8 校验资源点卡片（等级/储量/采集者/联盟）→ G9 对账「自动采集至清空」
G10 采集 → G11 创建部队 → G12 一键编成 → G13 读单程行军耗时 → G14 行军
G15 复读面板确认队列 +1 → G16 记账并算 freeAt，排下一次唤醒
```

**唤醒时刻的算法**（用户要求「不必卡死时间、留冗余、宁晚勿早」）：

```
etaAt  = 采样时刻 + 面板上该行的剩余秒数     ← 当前阶段结束
freeAt = etaAt + 单程行军秒数                ← 采集完队伍会自动回城，队列要等它到家才释放
wakeAt = freeAt + slackSeconds(默认 60) + 随机抖动(默认 0~20s)
```

单程行军秒数**只有派兵那一刻**能从「行军」按钮上读到，一旦离开那个页面就再也读不到，
所以它随本次派兵一起记账（按目标坐标）。读不出时走保守兜底，只会偏晚、不会偏早。

唤醒到点**只代表「该去看一眼」**，绝不等于「队伍已经回来了」—— 机器休眠会让定时器滞后，
所以到点后必须重新读一次面板校验。队列仍未空就指数退避 30s→60s→120s→240s→封顶 5min。

### 6.2 在面板里怎么用

1. **「采集配置」页**：左上角选实例，逐项配好，点「保存」。
   - 配置存在**该实例绑定的账号**里（`Account.scriptParams.gather.configJson`），
     所以**先在「账号」页建账号并绑到实例**，否则只能存进浏览器 localStorage，换台机器就没了。
   - 每个字段都写了「调大 / 调小分别付出什么代价」，改之前先读一眼。
   - ★ **「等级策略」配的是搜索下限，不是目标等级。** 游戏的匹配规则是「返回等级 **≥** 搜索值的点」，
     不是精确匹配。真机实测：把搜索值调到 1，连续搜 6 次返回的点依次是 8,7,7,7,7,8，一次都没等于 1。
     所以搜到 8 级点不是 bug，是正常结果。
   - 「启用自动采集」默认**关闭**。打开就是真的会派兵、真的占用行军队列。
2. **「采集总览」页**：打开卡片右下角的「自动调度」开关，调度器就开始按 ETA 干活。
   - 倒计时在**面板本地每秒递推**，不会为了刷新数字去截图（截图约 750ms，那样做等于持续占着模拟器）。
   - 「立即采样」按钮会真的开一次「部队管理」面板读一遍，读完自动关掉。
   - 识别不出来的字段会**如实标出来**（「坐标未识别」「行军时长为估算」），绝不编造。

### 6.3 命令行验证（不开面板也能跑）

四个 `live:*` 脚本直接驱动真机，用来排障与验收：

```bash

npm run live:panel          # 开一次「部队管理」面板读队列/倒计时/坐标，读完关掉
npm run live:run            # ★ 跑一整轮 runGatherCycle —— 会真的派出一支采集队
npm run live:recheck -- 150 # 采样 → 等 150 秒 → 再采样，校验本地 ETA 递推误差
```

留痕（jpg + ndjson 日志）落在 `docs/live/`。另有三个**离线回放**自检，拿 60 张真机截图跑，
不碰模拟器，改完识别相关代码请务必跑一遍：

```bash
npm run check               # = check:sched + check:gather + check:alerts + check:bot + check:stats + check:resources
                            #   共 24 + 28 + 174 + 76 + 73 + 93 = 468 项断言（约 40 秒，其中「道具页没打开」场景要吃两次 6s 超时）
```

其中 `check:alerts` 是异常检测与推送的离线自检（见第 7 节），同样不碰模拟器、也不发真实网络请求。

### 6.4 真机实测结论（踩过的坑，别再踩回去）

| 结论 | 为什么 |
|---|---|
| **卡片等级判据必须是 `>=` 不是 `==`** | 游戏返回「≥ 搜索值」的点，写成 `==` 会一直搜、永远不派兵 |
| **搜索面板会随分类整体左右平移** | 搜索按钮中心 x 实测 464/855/1269/1697/2115。面板内一切坐标都由 `tpl_btn_search` 的命中中心推出来，**不能写死** |
| **「等级 N」标签随滑杆手柄移动** | 每级右移 55.3px。必须先在宽带 ROI 里定位标签，再取它右侧的窄条读数字 |
| **「采集」不是一键编成按钮，是编成模式下拉框** | 点它会弹出 2x3 的模式菜单，菜单是**模态**的，会把下一次点击整个吃掉。所以 G14 做了「点完复验、按钮还在就再点一次」（复验是硬前置，绝不会派出两支队） |
| **世界地图判据不能只用放大镜** | `tpl_world_search_icon` 的镜片是**半透明**的，分数随镜片底下的地形漂移：草地 0.981，压着一座伐木场只有 0.794。改成和不透明的 `tpl_nav_city_toggle` 组成 anyTemplate |
| **世界地图上按 BACK 会弹「退出游戏」确认框** | 误点确定就退出游戏了。关面板一律优先「点面板外空地」或左上角返回箭头，只有认不出界面时才盲按 BACK，且**紧接着必须检查并取消**该确认框 |
| **字形集缺字时读数会「说谎」而不是报错** | 逐字位 argmax 会挑一个最像的现有字形顶上，产出一个格式合法、值却是错的串，正则拦不住。所以坐标这类字段把接受阈值抬到 **0.90**（读对 0.967~0.980，读错 0.787~0.789，能干净分开），宁可判「读不出」 |
| **配额记账不能只依赖坐标识别** | 「这支队是我派的、采的什么」全靠行内坐标对账，坐标读不出就全断。现在本轮自己派出去的队**无条件计入配额**（`dispatched` 是事实，不依赖识别），且「坐标读不出」的行一律当成自己的（少派而非多派） |
| **`adb input swipe` 偶发 `SecurityException`** | 实测重试即成功。adb 层不重试，重试必须由调用方做 |

### 6.5 已知缺口

- **`tpl_alliance_own` 缺失**（模板库里只有他方联盟的样例）。运行期会把「本方 + 中立」
  自动降级成**只接受中立**并告警 —— 方向是安全的（宁可少采也不把队伍派进敌方领地），
  但会漏掉本方领地里的加成点。补一张本方联盟缩写的模板即可恢复。
- **`dig_card_coord` 字形集缺 `0` 和 `4`**，含这两位的坐标一律判为「读不出」。
  影响面：目标去重、每种资源占了几个队列的记账、总览页的坐标显示。
  不影响 ETA 与派兵本身。补字形的采集点：部队管理面板行内「坐标:」右侧
  （`tpl_label_coord_row` 命中框 + `coordRoiRightOf`），注意**必须避开下方的下划线**
  （下划线会把所有数字连成一段，列投影切不开），实测可用切分参数 `y=308 h=28 polarity=dark thr=100`。
- **`dig_march_btn` 缺 3/4/6/7/8**，行军耗时含这些数字时读不出，freeAt 走保守兜底。
- **「驻扎中 / 集结中 / 战斗中」状态词、以及「队列已满 / 体力不足 / 无可用部队」的错误弹窗**
  都还没有模板。前者归为 unknown 状态、ETA 走兜底；后者只能靠超时兜底，失败原因不可辨。

## 7. 出事自动暂停 + Telegram 推送

挂机跑久了总会出事：**被顶号**（账号在别的设备登录，本端被踢回登录界面）、封号、服务器维护、
强制更新、模拟器崩了、adb 掉线……这时候面板还在闷头对着一个坏画面点来点去，
用户可能几个小时之后才发现。这一节就是解决这件事的：
**判定出事 → 立刻关掉该实例的自动调度 → 留一张现场截图 → 推一条 Telegram**。

### 7.1 它怎么判定「出事了」

分两层，**第一层已经在跑，第二层是预留的**。

**第一层：通用兜底（不依赖任何模板，覆盖全部卡死场景）**

采集状态机本来就有一套「未知界面兜底恢复」阶梯（通用关闭 → BACK 键 → 回家序列 → 冷启动 App）。
异常检测只做一件事：**数数**。数到阈值就出一条事件。

| 判据 | 默认阈值 | 事件 | 会暂停吗 |
|---|---|---|---|
| 恢复阶梯连续用尽（`step === 'G0'`） | 2 轮 | 需要人工介入 | ✅ |
| 采集轮连续失败（`outcome === 'error'`） | 3 轮 | 连续失败熔断 | ✅ |
| 连续打不开「部队管理」面板 | 3 次 | 模拟器或游戏掉线 | ✅ |
| 一直派不出采集队 | 120 分钟 | 长时间派不出队 | ❌（只提醒） |

★ **`queueFull` / `noResourceWanted` / `giveUp` / `staminaLow` / `circuitBroken` 一律不算失败，而且会把计数清零。**
队列 5/5 是挂机的**稳态**，把它当故障必然误报 —— 这是本模块最容易踩、也是唯一必须守住的一条。

阈值全部在设置页可改，改完立刻生效，不用重启。

**第二层：顶号精确识别（预留，模板还没采集）**

顶号没法凭空造样本（得拿另一台设备登录同一个账号），所以第二层写好了但还没有模板：
`tpl_dlg_kicked`（「账号已在其他设备登录」提示框）、`tpl_login_screen`（登录界面）、
维护公告、强制更新弹窗。

★ **模板不存在时它静默返回 null、自动降级到第一层，绝不会报错、绝不会中止采集。**
哪天你真被顶号了，把截图发出来、在「模板库」页裁一张图、id 填成上面那几个值之一，
第二层就自动生效 —— **代码一行都不用改**。

### 7.2 暂停是什么意思

暂停 = **把该实例的自动调度关掉**（`auto=false`），并且：

- 取消已经排好的唤醒 timer（不会再在坏状态上继续操作游戏）
- 把暂停原因、时刻、现场截图路径写进 `alerts-pauses.json`（**重启后不丢**）
- `scheduler.json` 里的 `auto` 也是 false，所以重启也不会自己跑起来
- 面板上该实例的卡片**整张标红**，顶上挂一条红色横幅写清原因与处置建议

暂停是**幂等**的：同一件事重复触发不会重复关调度、不会覆盖最初的暂停原因、
也不会重复推送（见 7.5 的冷却）。

**恢复**：点红条上的「恢复」按钮。它会清掉暂停记录 + 清掉失败计数 + 清掉推送冷却，
然后重新打开自动调度并立刻读一次面板。现场要是还没修好，它会马上再暂停一次 —— 这是对的。

> ⚠️ 「立即采样」按钮在暂停状态下**仍然会去操作模拟器**（这是既有行为）。要真正停手请用「恢复」按钮那条路。

### 7.3 ★ 去哪拿 Telegram bot token 和 chat id

**拿 Bot Token（两分钟）**

1. 在 Telegram 里搜 **@BotFather**（认准带蓝色对勾的官方号），点 Start。
2. 发 `/newbot`。
3. 它问机器人的显示名 —— 随便起，比如 `万龙看门狗`。
4. 它问机器人的用户名 —— **必须以 `bot` 结尾**，比如 `wanlong_watchdog_bot`；重名了就换一个。
5. 成功后它会回一段话，里面有一行形如：
   ```
   Use this token to access the HTTP API:
   123456789:AAEhBOweik6ad9r_QXsomethingsomething
   ```
   **只复制冒号两边那一整串**（`123456789:AAE...`）。
   ★ 最常见的错误是把 `HTTP API:` 这几个字或者结尾的空格/换行一起粘进去 —— 那样会报 401。
6. 以后想再看一次：给 @BotFather 发 `/mybots` → 选中你的机器人 → **API Token**。

**拿 Chat ID**

- **推给自己（私聊）**：
  1. 先**主动给你刚建的那个机器人发一条消息**（发个 `/start` 就行）。
     ★ 这一步不能省 —— Telegram 规定机器人不能主动私聊一个从没跟它说过话的人，
     省掉这步会报 403。
  2. 搜 **@userinfobot**，点 Start，它会回你的数字 id，形如 `123456789`（**正数**）。
- **推到群里**：
  1. 把机器人拉进群。
  2. 群里搜 **@getidsbot** 或 **@userinfobot** 拉进来看一眼群 id，形如 `-1001234567890`（**负数**，前面的减号要带上）。
  3. 拿到之后可以把那个查 id 的机器人踢掉。

★ 这里**只认数字 id**，`@某某频道` 这种写法不支持。

**填进面板**

设置页 → 「异常检测与推送」卡片 → 打开 Telegram 开关 → 填 Bot Token 和 Chat ID → 保存 →
**点「测试推送」**。手机上收到消息就说明通了。

失败的话，按提示的中文原因对号入座：

| 提示 | 怎么修 |
|---|---|
| Bot Token 无效（401 / 404） | token 复制错了。回 @BotFather 发 `/mybots` 重新复制，别带「HTTP API:」 |
| Chat ID 不对（chat not found） | id 填错了。私聊是正数，群是负数 |
| 机器人没有权限往这个会话发消息（403） | 私聊的话先给机器人发一条 `/start`；群的话把机器人拉进群 |
| 网络不通，连不上 api.telegram.org | 国内直连基本不通，得挂代理。面板走的是 Electron 的网络栈，**会遵守系统代理**，所以浏览器能开 Telegram 这里通常就能通 |
| 被 Telegram 限流了（429） | 短时间推太多了，把「推送冷却」调大 |

### 7.4 ★★ Token 是凭据，它去了哪、没去哪

Telegram 的 token 直接长在请求 URL 里（`https://api.telegram.org/bot<TOKEN>/sendMessage`），
所以**任何一次把 URL 带出去的动作都是一次泄漏**。本工程的处理是：

- token **只**存在于 `<数据目录>/alerts.json`，那个目录已被 `.gitignore` 覆盖（`.wl-data/`），
  另外 `.gitignore` 里还单独兜了一道 `alerts.json` / `alerts-pauses.json`
- 过 IPC 给面板的是 `AlertsConfigView`，**类型上就没有 `botToken` 这个键**；
  面板只拿得到打码值 `••••••后4位`
- 日志里只写打码后的配置
- 每一处 `catch` 的第一件事就是 `scrubSecret(...)`，把 token 换成 `***` 之后才允许它进
  错误信息 / 日志 / 面板
- 抓异常时**只取 message 和 cause，不取 stack**（栈里同样可能带 URL）

这几条有离线自检守着（见 7.7），改动推送相关代码后请务必跑一遍。

面板上想换 token 就直接填新的；想清空点「清除 Token」。
**输入框留空保存 = 保持原 token 不动**（这样改个冷却秒数不会把 token 抹掉）。

### 7.5 推送的限流与去重

- 去重键是 **`实例号 + 事件类型`**。同一个实例的同一种原因，默认 **10 分钟**内只推一次（可配）。
- 冷却期内被压掉的次数会记着，下次放行时在正文尾巴上补一句
  「（冷却期内还发生过 N 次同类事件）」。
- **冷却快照跟着 `alerts.json` 一起落盘** —— 不然一个还卡在坏状态的实例会在**每次面板重启后**
  立刻再推一条，重启几次就被轰几次。
- **只有真发出去了才重置冷却起点**。发送失败不占用冷却窗口，否则一次失败等于把这条告警吞了。
- **推送失败绝不影响暂停**：该暂停还是暂停，失败原因会写进暂停态、在红条上看得到，也进日志。

消息正文长这样（★ 时间是**北京时间**，因为游戏按北京时间运行，而宿主机时区不一定是北京）：

```
【需要人工介入】
实例 0（主号-王朝A区）
原因：连续 2 轮都回不到世界地图（未知界面恢复阶梯已用尽：通用关闭、返回键、重新拉起游戏都试过了）。
      游戏很可能被顶号踢回了登录界面，或者弹了维护/强制更新公告。
时间：2026-09-10 01:23:45（北京时间）
现场：outcome=error step=G0 恢复阶梯用尽次数=2
截图：alerts/inst0-g0-failed-1757462412345.jpg
处置：去面板看一眼那台模拟器现在停在什么界面，处理完点「恢复」。
```

### 7.6 想加新的事件类型怎么办

只需要在 `src/shared/alerts.ts` 的 `ALERT_TYPES` 里加一个值、在 `ALERT_SPECS` 里补一段中文文案
（标题 / 说明 / 处置建议 / 级别 / 要不要暂停 / 默认订不订阅）。
**通道代码、限流代码、面板代码一行都不用改** —— 设置页的订阅勾选列表、推送正文、
暂停红条的文案全是从这张表读出来的。

### 7.7 离线自检（不碰模拟器、不发真实请求）

npm run check:alerts        # 174 项断言：阈值判定、模板缺失降级、四类失败话术、
                            # ★ token 泄露实测、三道闸与冷却去重、

它已经并进 `npm run check`。跑的时候设备接口是假的（`resolveDevice` 直接抛）、
fetch 是假的（请求全部记在内存里）、数据目录是临时目录，**不会碰模拟器，也不会发一个真实网络请求**。

### 7.8 已知缺口

- **顶号模板还没有**。第二层目前只验证过「模板缺失时静默降级」这一半，命中路径要等真被顶号一次才能验。
- **暂停不会中断正在跑的那一轮**。调度器的采样与派兵没接 `AbortSignal`，
  所以暂停生效后可能还有一次已经在跑的操作会自己跑完；跑完之后就不会再有下一次了。
- **阈值（3 / 2 / 3 / 120 分钟）是拍的**，没有真实故障样本支撑。已经全做成设置项，
  日志里每次计数变化都有记录（`grep '采集失败计数'`），建议真机跑几天后按实际情况再定。
- **「实例管理」页的暂停提示只有一行**（「已暂停 · 类型」+「恢复」按钮），原因、处置建议与现场截图仍只在「采集总览」页的红条里。

## 9. 常见问题

**`npm run dev` 报 `Electron failed to install correctly`**
→ `node node_modules/electron/install.js`

**面板里实例列表是空的**
→ 雷电：`ldconsole.exe` 路径不对，或多开器里根本没有实例。命令行验证：
`D:\leidian\LDPlayer14\ldconsole.exe list2`（每行 `序号,名称,...,宽,高,dpi`）。
→ MuMu：MuMu 没开，或 `mumutool` 路径不对。命令行验证：
`/Applications/MuMuPlayer.app/Contents/MacOS/mumutool info all`

**实例列表里分辨率那一列标黄「不一致」**
→ 实例不是 2560×1440，模板会整体错位。到雷电多开器 → 该实例设置 → 分辨率改成自定义 2560×1440、DPI 360，重启实例。
也可以在面板里对该实例「更多 → 写入配置」填 `{"resolution": "2560,1440,360"}` 再重启。

**Windows 上每隔几秒闪一个黑色命令行窗口**
→ 某处 spawn 子进程没带 `windowsHide: true`。adb / ldconsole / reg 三处都已带上，新加的子进程照做。

**点「连接」报设备未就绪**
→ 实例还在开机中。实例状态要是 `running` **且**画面已经显示出来才行。

**模拟器刚开机、游戏还没打开，自动采集会自己把游戏拉起来吗？**
→ 会。采集流程与调度器采样在「认不出当前界面」时，都会先查前台包名：
不是游戏就用 monkey 把它拉起来，等到前台，再给足加载时间（冷启动实测 90 秒以上），
然后接着开部队面板。**你只要开模拟器就行，游戏不用手动点。**

只有两种情况仍需要人工：一是游戏拉起来后停在登录 / 公告 / 维护页（那不是自动化能替你做的决定），
二是模拟器实例本身没开机 —— 面板不会替你开实例，因为那要占几个 GB 内存，得你自己决定开几台。

★ 顺带一提：这个游戏用 `adb shell am start` **拉不起来**（会返回成功但进程起不来），
必须走 `monkey`。自己写脚本拉游戏时别踩这个坑。

**adb 报 `more than one device`**
→ adb 会把实例的 adb 端口自动扫描成 `emulator-XXXX`（MuMu 是 `emulator-5554`，雷电实例 1 是 `emulator-5556`），
和 `127.0.0.1:<端口>` 是**同一台设备的两个 transport**。
面板内部所有 adb 调用都强制带 `-s 127.0.0.1:<adb_port>`，不受影响；
你自己在命令行敲 adb 时记得也带 `-s`。

**截图很慢（>1s）**
→ 前台有游戏在跑就会这样（实测游戏在前台 ~770ms，切后台 ~280ms）。
另外单设备 screencap 吞吐上限约 4.3 帧/秒，这是模拟器的硬限制，并发抓不会更快。

**模板保存被拒绝，提示方差太低**
→ 换一块有图标或文字的区域重截。见第 4 节的规矩 1。

**自动采集一直在搜、就是不派兵**
→ 十有八九是把「等级策略」当成了目标等级。游戏返回的是**等级 ≥ 搜索值**的点，
判据必须是 `>=`；另外 `tpl_alliance_own` 缺失时策略会自动降级成「只接受中立」，
附近如果全是他方联盟领地就会一直换点。先跑 `npm run live:run` 看日志里每张卡片的判定原因。

**日志里说「点了行军」，可是队列一点没涨**
→ 上一步点的「采集」是**编成模式下拉框**不是一键按钮，它弹出的菜单是模态的，会把下一次点击吃掉。
G14 已经做了「点完复验、按钮还在就再点一次」，如果还不行，看留痕
`docs/live/00X-g14-before-march.jpg` / `-after-march.jpg` 两帧，一眼就能看出是点空了还是弹了别的框。

**流程在一块「明明就是世界地图」的画面上反复按 BACK**
→ `tpl_world_search_icon` 的镜片是半透明的，分数会随镜片底下的地形漂移（实测 0.981 → 0.794）。
世界地图判据已经改成它和不透明的 `tpl_nav_city_toggle` 组成 anyTemplate。
真出问题时先 `npm run live:probe` 看两张各打多少分。

**「采集总览」里坐标显示「坐标未识别」**
→ `dig_card_coord` 字形集缺 `0` 和 `4`。缺字时读数会「说谎」而不是报错，
所以坐标的接受阈值被特意抬到 0.90，读不出就判读不出。不影响 ETA 与派兵，只影响去重与显示。

**设置页说「主进程还没有注册告警通道（alerts:\*）」**
→ 面板起来的时候告警模块初始化失败了（不阻断启动，是设计内的降级）。
看终端里有没有 `[main] 告警推送模块初始化失败` / `[main] 告警中心初始化失败`。

**测试推送一直报「网络不通，连不上 api.telegram.org」**
→ 国内直连基本不通。面板发请求走的是 Electron 的网络栈，**会遵守系统/应用代理** ——
所以判断标准很简单：**同一台机器上浏览器能不能打开 telegram.org**。
浏览器能开而面板不行，才是 bug，请把日志发出来（日志里的 token 已经打过码，可以直接发）。

**实例卡片标红说被暂停了，但我已经把游戏弄好了**
→ 点红条上的「恢复」按钮，不要去拨「自动调度」那个开关 ——
只有「恢复」那条路会同时清掉暂停记录、失败计数和推送冷却。

**中文输入不可用 / `device:setupIme` 报 NOT_FOUND**
→ 需要 `resources/apk/ADBKeyboard.apk`，这个 APK 不在仓库里，得自己下载放进去。
`input text` 对中文是**静默丢弃**的，所以中文必须走 ADBKeyboard 的 base64 广播，没有替代方案。
不输入中文的话不影响任何其它功能。

## 11. 机器人菜单 / 截图 / 资源统计 / 数据统计

在第 7 节「出事自动暂停 + Telegram 推送」之上，机器人多了一套**菜单**，面板多了一页**数据统计**。
全部走同一条 `BotActionPort` 链路（`src/shared/bot.ts`），手机上点按钮、发命令、面板设置页里点「执行」跑的是同一段代码。

### 11.1 手机上的菜单

给机器人发 `/start` 或 `/menu`，底部会出现一排常驻按钮（Telegram 的 ReplyKeyboardMarkup，两行三列）：

| 按钮 | 等价命令 | 做什么 |
|---|---|---|
| 📊 状态 | `/status [实例号]` | 队列 / 在途 / 下次唤醒 / 自动调度 / 暂停原因 |
| 👥 账号列表 | `/accounts` | 每个账号：名称 / 绑定实例 / 启用 / 实例是否运行 / 自动调度 / 暂停原因 / 上次读面板 |
| 📷 截图 | `/shot [实例号]` | 截一帧**以图片形式**发过来，说明里带实例、北京时间、前台包名、游戏进程是否存活 |
| 💰 资源 | `/resources [实例号]` | 打开游戏「道具 → 资源统计」表读 4 行 × 2 列，读完还原到主界面再回文本 |
| 📈 今日统计 | `/stats` | 今日（北京时间）派兵 / 预计采集量 / 完成趟数 / 失败熔断 / 告警 / 暂停时长 |
| ❓ 帮助 | `/help` | 命令说明 |

- 截图 / 资源需要指定账号：没带实例号时先回一组内联按钮（`实例 0 · 主号`…）让你选，只有一个实例就直接执行。
- 仍然只响应设置里那一个 Chat ID；其它会话的消息与按钮一律忽略并记日志。
- 按钮文本是常量（`BOT_MENU_BUTTON`），**一个字都不能改**，改了旧键盘就对不上命令了。

### 11.2 截图与资源统计会碰模拟器，所以要抢锁

「📷 截图」「💰 资源」「🔁 重启游戏」都要驱动模拟器，动作层把它们包在 `scheduler.exclusive(实例, 动作名, fn)` 里：
与调度器的采样 / 派遣抢**同一把实例锁**，调度器正在开面板时机器人会排队等它做完，反过来也一样。
实例上有脚本（utilityProcess）在跑时直接拒绝：「实例 N 上正有脚本在跑（runId），截图稍后再试。」

「💰 资源」的流程：预检（前台是游戏、没有弹窗、在世界地图或城内、部队管理面板没开着）→ 点底部「道具」→
点右上「资源统计」→ 等标题模板出现 → 读一帧（任一格读不出就再读一帧合并）→ BACK → 点掉可能的提示 →
BACK → 用 `tpl_nav_city_toggle` / `tpl_nav_map_toggle` 校验回到了主界面。预检不过（比如部队管理面板开着）
**一个动作都不发**，直接回「当前不在主界面，稍后再试」；还原失败会留痕并报「读完资源统计后没能回到主界面，请打开模拟器看一眼」。

读数精度只有 **0.1 亿**（1000 万）—— 一趟魔水才 42 万，所以这张表**不能**拿来做日采集量的差值，
只作日切快照与粗对账。日采集量的主数据源是派兵记账（下一节）。

已知缺口：字形集 `dig_resstat` 目前缺 **5、8、逗号**，单位字缺「万」（现有截图里没出现过）。
含 5/8 的格子会判「读不出」并把原文回给你，**不会给出错值**；等表里出现这些字时用 tplkit 补裁
`dig_resstat_5` / `dig_resstat_8` / `dig_resstat_comma` / `tpl_resstat_unit_wan`（`resources/game-data/resource-stats.json` 已标 missing）。

### 11.3 数据统计（面板「数据统计」页 / 机器人「📈 今日统计」）

按**北京时间 0 点**切日桶（`src/shared/stats.ts` 的 `cstDateKey`，显式按 UTC+8 算，宿主时区无关；
已在 `TZ=America/Los_Angeles` / `Asia/Shanghai` / `UTC` 三种宿主时区下验证结果一致）。

| 统计项 | 来源 | 口径 |
|---|---|---|
| 派兵次数 / 预计采集量（按资源） | 派兵记账 `DispatchRecord.storage` | 默认勾「自动采集至清空」，一趟采集量 ≈ 派兵时读到的卡片储量（精确到个位）；储量读不出的那趟计 0 并单独计数 |
| 完成趟数 | 上次在外的队伍从部队管理面板上消失 | 资源类型按坐标反查派兵记账；查不到按当日派兵最多的资源归类并记日志，**只作参考** |
| 失败 / 熔断 | 采集轮 `outcome === 'error' / 'circuitBroken'` | — |
| 告警条数 | `AlertCenter.raise` | 含被冷却压掉的 |
| 暂停时长 | 调度器 `setAuto` **真的翻转**时通报（`SchedulerDeps.onAutoChanged`） | 面板开关、告警自动暂停、机器人 /pause /resume 三条路都经它，唯一来源；跨 0 点在边界切开 |
| 资源统计快照 | 「💰 资源」/ 面板「读一次资源统计」 | 每天最多 48 张，页面上给「日初 / 最近」对比，差值小于 0.1 亿显示 ≈0 |

落盘：`<dataDir>/stats/<YYYY-MM-DD>.json`，每天一个文件，保留 90 天，空桶不写。
面板「数据统计」页：今日六格 + 按资源占比条 + 按实例表 + 资源统计快照卡 + 近 14 天表（点行切换到那天）。

「💰 资源」在真机上的导航 / 淡入动画 / 还原，以及城内 HUD 的「道具」按钮位置是否与世界地图一致。

## 12. AI 顾问：认不出界面时问视觉大模型 + 模板自学习

采集流程与调度器都有一条「模板全不命中、认不出当前界面」的分支，以前只能盲按 BACK 试探，六次不行就暂停实例。
最常见的元凶是**活动弹窗**（带「前往」和右上角 ×），而它的 × 模板一直缺着 —— 弹窗不可复现，没法提前裁。

AI 顾问把这一格交给视觉大模型（任何 **OpenAI 兼容接口 + 支持图片输入**的模型），在「盲按 BACK 之前」插一次：

1. 把当前截图缩到 1280 宽发过去，让模型分类界面、选择按钮，并结合正文评估点击后果和风险。可选择关闭、取消、确认/继续/重试、返回或不动。
2. 只有后果明确的低风险点击可执行。确认类动作至少需 85% 置信度，并用新截图再次独立评估；购买、资源消耗、账号变更等操作或风险不明时暂停实例，不继续按 BACK。关闭/取消仍可做局部放大精定位。
3. 点击前检查前台应用及画面是否变化；同一确认 60 秒内只执行一次。点击后截图复验，确认无效或执行结果不明时暂停；画面变了但仍认不出则继续判断。
4. ★ **自学习**：点掉弹窗后回到了已知界面（世界地图 / 城内 / 面板…），就把点击前那一帧里的关闭按钮裁成模板
   存进模板库（第一张就是采集流程一直缺的 `tpl_btn_close_popup`，之后是 `_ai2`、`_ai3` … 最多 8 张）。
   下次同样的弹窗 1 毫秒本地解决，不再问 AI。裁模板走正式的视觉层，方差守卫、去重（已有模板能认出就不再学）都在。

### 12.1 配置

设置页「AI 顾问」卡：

| 项 | 说明 |
|---|---|
| 接口地址 | 填到 `/v1` 这一层，面板自己拼 `/chat/completions`。阿里云百炼：`https://dashscope.aliyuncs.com/compatible-mode/v1` |
| API Key | 凭据。只存 `<dataDir>/ai.json`，界面只显示后 4 位，不进日志、不进错误信息、不过 IPC 桥。留空 = 不修改 |
| 模型名 | 必须支持图片输入。百炼的 `qwen3.8-flash` 是多模态模型（图 / 视频都收），也可用 `qwen3-vl-plus`、`qwen3-vl-flash` |
| 测试连接与视觉能力 | 发一张合成图（大红字母 W）问「最大的字母是什么」：认出 W ⇒ 支持图片；答非所问 ⇒ 判「不支持图片」；400 提到 image ⇒ 纯文本模型 |
| 每小时最多问几次 / 同实例冷却 | 识别出错时流程可能反复认不出界面，这两道闸防止烧钱。默认 20 次 / 20 秒 |
| 最低置信度 | 模型自报置信度低于它的建议不执行，默认 0.5 |
| 局部放大精定位 / 自学模板 | 默认都开 |

确认动作使用 `max(最低置信度, 0.85)`；二次复核计入请求额度，但跳过同实例冷却。耗时和费用取决于配置的模型与网络。**截图里有你的账号、服务器、联盟信息，会发到你填的接口。**

### 12.2 它在哪里介入

- 采集流程 G0（`src/main/game/gather/navigation.ts` 的 `ensureWorldMap`）：找不到 × 模板之后、盲按 BACK 之前。
- 调度器采样（`src/main/scheduler/troopPanel.ts` 的 `ensurePanelOpen`）：顶号探针没命中之后、点 × / 按 BACK 之前。
  AI 处理成功时采样器收到 `'recovered'`，重新截图再判，不按 BACK。

两条链路都按「`tpl_btn_close_popup` 或以它为前缀」扫描关闭按钮模板，AI 自学的变体不用改代码就能用上。
