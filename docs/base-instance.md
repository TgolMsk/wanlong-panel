# 基础实例

## 使用

1. 打开「设备与账号 → 模拟器实例」。
2. 在准备好的实例行点击「更多 → 设为基础实例」。实例 0 也可使用。
3. 关闭基础实例，再点击「新建实例」。默认选择「克隆基础实例」，数量支持 1–8。
4. 克隆沿用模拟器的应用、游戏数据和配置。默认创建完成后进入[账号登录向导](account-login.md)：绑定面板账号、手机号验证码登录、检查进入游戏。系统盘中的登录状态可能一并复制，请按需切换账号。
5. 临时需要全新环境时，在新建弹窗选择「空白新建」。可通过列表上方或该实例的「更多」取消基础实例。

基础实例可手动启动维护；登录向导和自动任务在副本中进行，克隆时要求源实例已关闭。面板创建、克隆和删除互斥，克隆期间源实例也不能被面板启动、重启、改配置或交给脚本/自动采集。

## 保存与异常

- 设置保存在当前运行数据目录的 `instance-defaults.json`，沿用模拟器安装位置和数据目录隔离；面板重启后继续生效。
- 源实例丢失时明确报错，不自动改为空白新建。MuMu Windows 还记录 CLI 的创建时间戳，防止实例删除后复用相同编号导致复制错误来源；不提供稳定身份字段的旧驱动只能按编号/实例路径检查。
- 在面板删除基础实例后自动清除设置。外部多开器操作后，需要刷新并重新设置失效的来源。
- 多份副本依次从同一个基础实例复制。中途失败保留已生成副本，并报告已发现的新编号；先检查列表，再补建缺少数量。
- 面板内占用锁不约束外部多开器，克隆期间请勿同时在多开器创建、删除或启动源实例。

## 验证

`npm run check:runtime` 包含基础实例的隔离临时目录测试：默认创建方式、编号 0、持久化、失效来源、同源批量、并发互斥、部分成功、损坏设置保护及 IPC 调用链。它使用受控驱动，不创建或删除真实模拟器。

`npm run check:mumu` 检查现有 MuMu 驱动解析和配置兼容性。构建检查使用 `npm run build`。
