# 项目完善与图片匹配审查

日期：2026-09-15。基于本机当前工作区、现有模板库和仓库历史截图。

后续实施：本报告中的五项重点已完成代码改进，见 [运行可靠性与模板识别完善](runtime-improvements.md)。下面保留审查时的证据；新的复核入口为 `npm run check:runtime`。

## 结论

图片去底可以明显改善动态背景下的识别，项目已经有完整的多帧差分去底功能。本轮验证了已有掩码的效果，未重新制作或覆盖生产模板。

当前更值得优先完善的内容是：暂停后的执行控制、任务互斥、模板无损抓帧，以及模板验证工具。导航简化解决了入口分散，下面这些改进会直接影响长期运行的可靠性。

## 2. 哪些图片适合去底

| 类型 | 建议 | 原因及验收重点 |
| --- | --- | --- |
| 地图上的镂空、半透明导航图标 | 沿用多帧差分掩码 | 背景地形会变，图标主体稳定；当前已有实测收益。采样时只移动地图，保持控件位置不变。 |
| 固定纯色底上的图标、文字 | 增加“选底色＋容差＋掩码预览” | 可通过底色生成 alpha；需要防止同时删掉图标中同色的细节，允许局部恢复掩码。 |
| 进度条上的白字、倒计时 | 沿用并扩充现有背景压平策略 | 绿色／灰色进度边界会穿过文字；保留描边灰阶更有利于区分相似数字。模板与输入必须同样处理。 |
| 活动弹窗关闭 X | 固定小搜索区域，保留 X 和必要轮廓，评估去底 | 需要补不同活动、不同底色的真实正样本，以及没有关闭按钮的负样本；单个通用 X 特征较少。 |
| 采集状态文字 | 比较现有灰底／绿底变体与背景压平 | 先用各行真实画面回放，确认去底后仍能区分采集中、行军中、返回中。 |
| 开关、勾选框、资源类别 | 保留状态相关颜色或增加颜色校验 | 颜色本身可能就是开／关或类别信息；去掉后可能失去区别。 |

### 实现原则

1. 去底应生成真正的 alpha 掩码，背景像素不参与匹配。只把模板底色涂白或涂黑，背景依然参与计算。[OpenCV 掩码参数说明](https://docs.opencv.org/4.13.0/df/dfb/group__imgproc__object.html)
2. 多帧差分没有自动位置配准；主图标发生位移时应提示重新抓帧，不能靠放宽容差掩盖错位。
3. 数字不应只保留一片纯白前景：会损失描边和灰阶，也可能触发项目现有的低方差保护。
4. 保持现有默认匹配算法及保护条件，优先调整模板、局部搜索区域和分场景预处理；阈值应根据正负样本分布逐项确定。
5. 建议模板验证页支持批量正负样本回放，展示最低正样本分数、最高负样本分数、位置偏差、耗时和掩码覆盖率，并保留模板版本以便回退。

## 3. 视觉链路优先完善项

### V1：模板抓帧改为无损 PNG

**确定事实：**编辑器主帧与差分帧只向 `device:capture` 传入宽度。即使勾选“原始分辨率”，仍使用默认 JPEG 品质 70。尺寸原始不代表像素无损。

- `src/renderer/src/views/TemplateEditor.tsx:257`、`:304`
- `src/main/handlers/device.ts:191`、`:203`
- `src/shared/constants.ts:186`

建议增加模板专用无损 PNG 抓帧，让微小字形和 RGB 差分用原始像素制作。验收应同帧对比 JPEG／PNG 模板的得分及掩码稳定性，本轮尚未测量这一改动的收益。

### V2：透明字形扩展前补齐多峰匹配的 mask

`src/main/game/vision/matchAll.ts:80` 无条件调用不带 mask 的 `matchTemplate`。`PreparedTemplate` 即使带有掩码，这条寻找多个字形位置的链路也不会使用。

调用方包括 `src/main/game/vision/digits.ts:101`，进而用于采集等级与资源数字识别。当前字形模板未发现使用掩码，所以这是扩展兼容缺口，不能据此断言现有数字已错读。

建议补掩码尺寸校验、带掩码匹配及异常分数过滤。用相同字形出现在不同背景、同一数字重复出现、纯色负样本进行验证。

### V3：补独立视觉测试与可重复回放

`scripts/sched-offline-check.ts:35`、`:55` 依赖本机 `.tplkit/frames`；相关具名 alpha 测试也依赖特定截图。当前工作区缺少该目录，完整检查不能作为已通过的验收依据。

建议拆出不依赖私有截图的基础视觉测试：透明掩码、低方差、稀疏掩码、尺寸异常、多峰匹配及缩放。真实游戏截图另外回放，并报告缺失样本，避免静默跳过后误以为覆盖完整。

## 4. 功能可靠性发现

以下按修复优先级排列。F1 已离线动态复现；其余来自调用链审查，尚未模拟故障或实机复现。

### F1／高：关闭自动后仍可能进入派遣

`setAuto(false)` 取消后续 timer，但 `onWake` 只在入口检查自动开关。若关闭自动发生在等待采样期间，采样完成后仍可进入派遣 hook。采集流程已有取消信号支持，但该调用未传入。

- `src/main/scheduler/index.ts:284`、`:649`、`:697`
- `src/main/game/gatherRunner.ts:378`
- `src/main/game/gather/session.ts:185`

离线复现使用生产 `onWake`、`setAuto` 和实例锁，替换采样、存储和派遣为假实现，没有初始化真实调度器：

```text
假采样挂起
setAuto(false) 返回 auto=false、nextWakeAt=null
放行采样，返回空队列 0/5
派遣 hook 被调用 1 次，收到 auto=false
```

预期调用 0 次，实际 1 次。证明关闭自动后仍会进入派遣入口；没有执行真实派兵。

复现：`node scratchpad/recognition-audit/pause-dispatch-repro.mjs`。源代码与 JSON 结果在同目录。本复现脚本的退出码 0 表示成功复现当前缺陷，不表示系统正确。

建议：采样后与取得派遣锁后检查自动状态；实例级取消信号贯穿采集；暂停时取消后续动作，界面显示“正在停止／已停止”。

### F2／高：脚本与自动采集的互斥不完整

调度采样会检查运行中的脚本，但脚本启动没有反向取得调度实例锁。此外，脚本启动在设备／脚本／账号读取前检查占用，读取完成后才登记任务；并行请求存在同时通过检查的窗口。

- `src/main/scheduler/index.ts:473`
- `src/main/index.ts:293`
- `src/main/orchestrator/index.ts:156`、`:230`

建议将脚本、采集、机器人动作纳入统一实例占用管理，在第一次异步等待前预占，失败时释放。用可控假设备与假 worker 验证同实例双启动和脚本／采集竞争。

### F3／高：数据目录与模拟器热切换缺少完整状态切换

设置变更更新全局路径／驱动，但没有同时停旧任务并重新加载所有有状态模块。调度状态在初始化时读取，保存时却实时取新路径；旧内存状态可能写入新目录。实例仅以数字 index 标识时，两个模拟器的同号实例也可能继承彼此的状态。

- `src/main/index.ts:867`、`:961`
- `src/main/scheduler/index.ts:183`、`:204`、`:798`
- `src/main/ai/advisor.ts:108`、`:448`

建议先采用“关闭任务后保存、下次启动生效”，再实现完整热切换事务。长期应把模拟器种类、安装位置和实例标识纳入身份，区分打开已有数据目录与迁移数据。用临时 A/B 目录和两个都含 index 0 的假驱动验证隔离。

### F4／中：多实例采集状态保存可能互相覆盖

`src/main/game/gatherRunner.ts:183` 对共享 JSON 采取“读全量 → 修改本实例 → 直接写回”，不同实例的锁不能串行这个共享文件；两个保存同时读到旧快照时可能丢掉另一方更新。写入中断也可能产生坏 JSON，当前读取失败会按空状态处理。

建议采用串行写队列＋临时文件替换，或每实例独立文件。通过可控文件 I/O 验证两个实例并行保存均被保留，并验证写入失败后原文件仍可解析。

## 5. 建议实施顺序

1. 修复暂停与实例互斥，并用离线竞争测试验证。
2. 模板专用无损抓帧，补透明多峰匹配兼容。
3. 加底色取样、掩码编辑与批量回放；先试地图图标、活动关闭按钮和状态文字，每类都有正负样本后再替换。
4. 完善目录／模拟器切换、状态文件写入和独立视觉检查。

本轮交付为审查报告及本地复核脚本；未修改生产识别逻辑、模板或自动任务状态。此前导航、布局与 logo 的本地改动仍保留。
