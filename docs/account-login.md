# 新实例账号登录

## 使用

1. 在实例页设置基础实例并关机。新建时默认勾选「创建后设置账号并登录游戏」。
2. 为副本选择未绑定的面板账号，或填写一个备注名新建账号，点击「绑定账号并启动游戏」。
3. 手机号登录页出现后，点击「刷新登录步骤」。输入手机号、确认游戏协议，再点击「发送验证码」。
4. 输入收到的 6 位验证码，点击「提交验证码」。游戏填写完验证码后自动提交；面板不会保存验证码。
5. 等待游戏加载，关闭公告，回到城内或世界地图。确认是目标账号，点击「检查登录并启用账号」。

本轮目标是登录并进入游戏。已有角色可能自动进入；大区选择和新建角色仍可在画面中手动操作，不自动选区。

实例行「更多 → 账号登录」及账号页「登录／继续登录」都能重新打开向导。中途退出保留实例和账号配置，账号显示「待登录」，再次打开可继续。基础实例本身不能进入登录向导。

手机号／验证码以 Android 数字输入完成，不依赖第三方输入法；实测 MuMu Android 15 会拒绝 `ime enable/set`。普通预览的中文输入仍使用原来的 ADBKeyboard 机制。

## 运行规则

- 登录从第一处异步操作前占用实例，与脚本、自动采集、实例删除和重启互斥。已有任务占用时先结束该任务。
- 登录开始后关闭该实例自动采集，新账号保持停用。完成主界面检查后仅启用账号，自动采集由用户另行开启。
- 取消会中止后续输入，等待已发送的设备操作结束才释放实例。重新打开不会重复创建账号。
- 普通账号编辑不能伪造登录检查结果；改绑实例后重新检查。MuMu 创建时间戳用于识别实例被删除后编号复用。
- 手机号、验证码只在调用过程中使用；状态只返回掩码手机号，输入异常不返回原始 ADB 参数。登录画面不交给 AI 分析。
- 手机号及验证码控件通过新鲜的 Android UI 树定位。原生页面无法识别、遇到额外验证或未知提示时保留画面，允许人工处理。
- 游戏主界面检查沿用当前模板库。缺少对应阵营模板时会提示配置，不把未知画面当作成功。

## 为后续 API 保留的接口

核心服务在 `src/main/login/coordinator.ts`，不依赖 Electron 窗口；Electron IPC 只是当前的传输适配器。设备驱动、账号存储、基础实例查询、状态通知均通过依赖注入提供。

| 服务操作 | 当前 IPC | 用途 |
| --- | --- | --- |
| `begin(request)` | `login:begin` | 返回会话 id，异步准备实例与游戏 |
| `session(index)` | `login:session` | 查询阶段、消息、界面步骤 |
| `command(id, command)` | `login:command` | 检查页面、发送短信、提交验证码、重发 |
| `input(id, input)` | `login:input` | 同一实例锁内的人工辅助点击、按键和数字输入 |
| `verify(id, confirmed)` | `login:verify` | 用户确认 + 游戏主界面检查，完成账号初始化 |
| `cancel(id)` | `login:cancel` | 取消并等待已开始的操作收尾 |

`LoginCommand` 必须携带 `requestId`。同一会话内，相同编号与相同参数返回同一次操作结果；相同编号对应不同参数会被拒绝。即使调用方等待超时，也应使用原编号重试，不能重新生成编号并重复发短信。需要重新执行失败操作时使用新编号。

状态流：`preparing → starting → awaitingLogin → verifying → completed`。错误和取消分别为 `failed`、`cancelled`；检查未进入主界面会回到 `awaitingLogin`。原生 UI 步骤 `phone/code/game/manual` 只是当前屏幕判断，其中 `game` 不代表已通过最终登录检查。

本次没有开放 HTTP 端口。后续 HTTP 层可将会话映射为 `/v1/login-sessions`，通过轮询或事件流返回状态；鉴权、每个调用方的账号／实例权限、短信限流、断线后会话回收和跨进程幂等存储在开放外网前接入。

自动采集继续使用 Scheduler，通用脚本使用 Orchestrator，二者和登录共用 `instanceAccess`。后续打怪／任务流程应作为独立任务类型注册，由统一任务服务启动、取消、查询状态，继续使用同一个实例占用机制。不要让 HTTP handler 直接调用 ADB 或另起一套采集循环。
